# WebUI 使用手册

> 适用版本：内嵌前端（`internal/api/index.html`，Vue 3 单页，无 Node 构建链）。
> 本手册描述面板界面的布局、各页面功能与常见操作流程。

## 1. 访问与登录

浏览器打开 `https://<主机>:8787`（自签证书首次需手动确认；未配置 TLS 时的明文 HTTP 仅建议在 127.0.0.1 使用）。

- 首次登录会强制要求修改初始密码（至少 8 位，含字母与数字）。
- 勾选「记住我」后 30 天内免登录（会话落盘，面板重启不掉登录）。
- 登录页提供 `/panel.crt` 证书下载，安装一次即可消除浏览器警告。

## 2. 界面布局

整体为「侧栏导航 + 顶栏 + 内容区」结构：

```text
┌──────────┬────────────────────────────────────┐
│ 侧栏      │ 顶栏：dae 状态 · pid · 刷新 · 退出  │
│ (分组导航) ├────────────────────────────────────┤
│          │ 内容区（当前页面卡片）               │
└──────────┴────────────────────────────────────┘
```

- **顶栏状态徽标**：dae 服务状态（active 为绿，其它为红）、pid、进度码；订阅源有变化时会出现红色「订阅 N 条有变化」徽标，点击直达订阅源更新页。
- **侧栏导航分组**：共 6 组 16 页，见下表。
- **窄屏（<768px）**：侧栏收起，点顶栏「☰ 菜单」展开；内容单列。

## 4. 核心流程：内容层（结构化配置）

内容层是日常最常用的页面，从上到下依次是：

1. **告警条**（按需出现）：
   - 「模型解析告警」：线上配置格式未完全解析。
   - 「线上是单文件布局」：说明应用时会改为 include 布局（自动备份，可回滚）。
   - 「面板模型与线上配置不一致」：线上可能被手工改过；此时点应用会**覆盖**线上改动，可先点「从线上重新解析」同步。
   - 「模型检查发现 N 个问题」：不阻断保存，但逐条列出会让规则失效或 reload 失败的问题。
2. **操作按钮**：
   - 「校验+备份+reload 应用」——唯一写盘生效的入口；
   - 「预览生成结果（不写盘）」——先看看会生成什么（页面底部还有一组「预览生成结果 / 校验+备份+reload 应用」，功能相同，滚动到底不用回顶部）。
3. **订阅 (subscription)**：名称 + 来源。推荐先到「订阅源更新」拉成本地镜像（`file://subs/xxx.sub`），再用下拉选择——dae 只读本地文件，不重复消耗上游 token。
4. **分组 (group)**：名称、策略（min_moving_avg / min_avg10 等）、过滤规则（每行一条）、**组级调优**（可选，textarea 每行一条，如 `check_interval: 30s` / `check_tolerance: 1s`，原样写入该组；留空则继承 global）。按钮「+ DNS 专用组（dnsnode）」可一键添加 DNS 专用组（policy `min_avg10` + 上面两条调优 + 港/日/新/台四条 filter）；已有同名组时只提示、不重复添加。组级调优与「全局」里的健康参数都会被写进渲染结果，因此点「应用」不会把它们抹掉。
5. **分流规则 (routing)**：自上而下首条命中生效，可调序；系统安全规则（内网/回环/本机进程直连）自动前置注入，不在此表内。底部 fallback 兜底出站。
6. **规则试算**：输入域名（如 www.youtube.com）点「试算命中」，用当前**未保存**的规则试算。
7. **全局 / DNS（高级原文）**：两个 textarea 直接编辑原文，代码编辑功能保留。

**重要**：本页没有单独「保存」按钮。输入框改动只暂存在浏览器里，**必须点「校验+备份+reload 应用」才写盘生效**。应用流程 = 渲染 → dae validate → 备份 → 写入 → dae reload → 校验结果，失败自动回滚。

### 订阅·分组页（只读 + 测速）

这一页只读，不改任何文件：

- 顶部按钮「刷新」（重新解析订阅与分组）与「全部测速」（对当前列出的节点端点逐个测 TCP 建连延迟）。
- 每个订阅一张卡：订阅名、来源（`file://subs/xxx.sub` 或 http(s)）、节点数，以及节点表（协议 / 地址 / 端口 / 备注 tag / 延迟 / 每行一个「测」按钮）。
- 每个分组一张卡：策略与命中节点数；若命中 0 个节点会黄字提示「检查 filter 或订阅是否正常」。
- 延迟判定：**≥3 秒视为不可达**，按延迟分档着色（绿/黄/红）。

用途：排查「分组为什么没节点」（filter 写错、订阅没拉到、节点名不含关键词）最快的地方；测速只是诊断，不参与 dae 的选路（真正选路由 dae 自己的健康检查决定）。

### DNS 页

结构化编辑 dns 块：上游服务器 → 请求规则（按域名/类型决定问哪个上游）→ 响应规则（按返回 IP 决定接受还是丢弃）。提供「从当前配置重新载入」「填回默认值」「渲染预览（不写盘）」与「保存到模型并应用」，应用走同一套校验+回滚事务。

## 5. 订阅源更新

1. 添加上游订阅（URL + UA）。
2. 手动或巡检拉取：上游返回 Clash/Mihomo YAML 时自动转成节点链接，存为本地镜像。
3. 变更只报告差异（新增/删除/变化节点），确认后才应用；上游失败不会覆盖最后一次有效结果。
4. 顶栏出现「订阅 N 条有变化」时点击直达本页查看明细。

## 6. 自建聚合

把多个订阅源合并成一份只含节点的镜像订阅：

1. 「预览」查看合并结果（dry-run）。
2. 「生成」产出聚合文件。
3. 「切换」预览差异后确认应用——切换会修改 live 配置（可回滚），有明确 confirm 弹窗。

## 7. 接入与组网（接入向导 / 组网 / 安装与初始化）

分步式安全接入流程（把流量送到 dae 面前）：

1. **只读探测**本机能力（失败则降级为只读观测模式）。
2. **档位推荐**：B1 旁路由单机 / B2 主路由 DHCP / A 网关（同机）/ 观测，附推荐原因。
3. **计划预览**：点「生成接入计划」产出 dae 配置片段、nft 片段、人工步骤、回滚方案与自检清单。计划恒为 dry-run，且带指纹（fingerprint）。
4. **应用**：二次确认后携带该指纹提交——写自有片段 `config.d/panel-access.dae` + dae validate + reload + 建自有 nft 表，任一步失败自动整体回滚；指纹不匹配会被拒绝（防止计划过期后误用）。
5. **自检**：应用后自动跑一次「运行自检（只读）」，也可随时手动点，逐项展示通过的/待确认的检查项。
6. 想撤掉接入时点「**回滚接入变更**」（有独立 confirm）：删自有 nft 表 → 备份并移除 `panel-access.dae` → dae reload。

面板只写自有片段（`config.d/panel-*.dae`）与自有 nft 表（`panel_*`），不碰系统 DHCP/PPPoE/NAT 与 `/etc/config/*`。

### 组网

EasyTier 异地组网（只读状态 + 启停服务）：通过 WSS(443/自定义端口) 伪装 HTTPS 流量打通两台设备。页面展示 `easytier-cli` 的节点表与路由表，提供启动/重启/停止按钮。面板本身不生成 EasyTier 配置。

### 安装与初始化页（从零到能跑）

这一页负责「装 dae → 生成最小可用配置 → 启动」。面板必须以 root 运行才能执行，否则只能看状态。**所有动作都可先 dry-run 看它要执行什么。**

**现场状态卡**（点「刷新状态」）：运行身份（root / 非 root）、服务管理器（systemd / procd）、APT 是否可用、dae 是否安装与运行（含版本）、入口配置文件（字节数 + 是否面板托管 + 路径）、主体配置是否存在、内核能力（BTF 是否可用、memlock 上限）。

**一键操作卡**：

| 按钮 | 做什么 |
| --- | --- |
| 安装 dae | APT 装有则用 APT；无 APT（OpenWrt/iStoreOS）走官方静态包：选 arch+avx2 → 下载解包 → 装到 `/usr/bin/dae` → 写 procd 脚本 → 重启服务 |
| 生成初始配置 | 写 `/etc/dae/config.dae` + `config.d/panel-core.dae`（tproxy 12345、`wan_interface: auto`、DNS 223.5.5.5、无规则时 `fallback: direct`）；**先备份，`dae validate` 失败立即回滚** |
| 启动 dae / 停止 dae / 重启 dae | 走服务管理器（systemd 用 `systemctl`，OpenWrt 用 `/etc/init.d/dae`） |
| dry-run 安装 / dry-run 初始化 | 只列出将执行的命令与结果，不落盘 |

注意：若目标配置文件已有**非面板托管**的内容，「生成初始配置」会拒绝覆盖；确实要替换需走 API 并带 `force=true`。

**执行记录卡**：逐步列出步骤名、实际命令、结果（成功 / 失败 / 已跳过(dry-run)）与输出片段，失败原因直接显示在下面。
## 8. 观测类页面

- **流量/命中**：DNS 命中排行等；数据来自真实采样，注明采样周期，不是实时大屏。
- **字节统计**：按 `--bytes-interval`（默认 10 秒）采样，socket 计数器 + `--bytes-iface` 网卡总量，按节点/客户端归并；未启用时页面会说明。

## 9. 审计日志

记录登录、应用、回滚、暂停、订阅更新等操作的 JSONL 审计（按大小轮转）。支持筛选查看，可导出 CSV / JSONL。敏感字段已脱敏。

## 10. 危险操作与确认

以下操作有明确 confirm 确认或影响预览：

- 应用配置 / 切换聚合订阅（修改 live，可回滚）
- Geo 数据更新（替换 dat 后 reload）
- 接入向导：应用（带计划指纹校验）与「回滚接入变更」
- 整段配置应用
- 运行探测页的「应急 suspend」与「回滚最近备份」（直接作用于 live 入口配置）
- 组网页的 EasyTier 启停

## 11. 界面设计规范

前端遵循仓库设计系统（深色主题、语义色 token）：

- 颜色只表达语义：绿=正常/成功，黄=警告/待处理，红=失败/危险，蓝=主交互/信息，灰=未知/非活动；状态同时有文字，不只靠颜色。
- 配置、日志、IP、端口使用等宽字体。
- 所有交互控件支持键盘访问，焦点态清晰。
- 未实现的功能不显示假状态；状态读取失败显示「暂时无法获取」而非沿用旧的成功态。

（本节即当前界面的规范摘要；界面实现见 `internal/api/index.html`。）
